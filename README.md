# 영종에서의 3일

영종도 2박 3일 여행을 관리하는 모바일 웹앱입니다. 기본 기능은 별도 설치 없이 `index.html`로 동작하며, 함께 쓰기는 Supabase 연결 후 사용할 수 있습니다. 배포할 때 `cloud-sync.js`와 `cloud-ui.js`도 함께 포함하세요.

## 실행

`index.html`을 브라우저로 열거나, 저장소에서 아래 명령을 실행한 뒤 브라우저로 접속하세요.

```sh
python3 -m http.server 8000
```

준비물 카테고리와 항목, 차크닉·카페·맛집 후보, 1~3일차 일정을 관리할 수 있습니다. 이름을 누르면 수정하고, 항목 또는 카테고리 제목 줄을 좌우로 밀거나 오른쪽 × 버튼을 누르면 삭제 확인 창이 열립니다. 길게 누른 뒤 위아래로 끌어 순서를 변경합니다. 항목은 같은 카테고리 안에서 정렬하며, 일정의 날짜 순서는 고정됩니다. 카테고리의 ＋/− 버튼으로 접거나 펼칩니다. 체크박스는 완료 상태만 변경합니다.

키보드에서는 이름에 초점을 맞춘 뒤 Enter 또는 Space로 수정, Delete로 삭제 확인, Alt+위/아래 방향키로 순서를 변경할 수 있습니다. 세로 스크롤은 길게 누르기 전까지 일반 스크롤로 동작합니다.

준비물 탭에서 **미체크만 보기**를 누르면 미완료 항목만 카테고리별로 모아 볼 수 있습니다. 체크하면 즉시 숨겨지며, **전체 보기**로 원래 목록으로 돌아갑니다. 필터는 데이터와 기존 접기 상태를 변경하지 않습니다. 필터 상태에서도 수정·삭제·드래그 정렬이 가능합니다.

## 저장과 백업

- 변경 즉시 브라우저 `localStorage`의 고정 키 `yeongjong-travel-checklist`에 저장합니다.
- 앱 파일을 업데이트해도 같은 브라우저와 사이트 주소에서 기존 데이터가 유지됩니다. 초기 데이터는 저장 데이터가 없을 때만 생성됩니다.
- 기본 준비물은 12개 카테고리, 204개 개별 항목입니다. 세면·위생과 야외 차크닉·캠핑의 물티슈는 각각 별도 항목입니다.
- 데이터 형식 버전 `1`과 기존 저장 키를 유지합니다. 이전 버전 백업도 복원 시 자동으로 목록을 확장합니다. 지원하지 않는 버전 또는 손상된 데이터는 자동으로 덮어쓰지 않습니다.
- 기존 카테고리·항목, 체크 상태, 수정 내용, 접기 상태, 정렬, 장소와 일정은 보존합니다. 새 기본 카테고리는 기존 목록 뒤에 추가하므로 기존 사용자의 카테고리 수는 12개보다 많을 수 있습니다. 같은 이름의 기존 개별 항목은 한 번만 연결하고 체크 상태를 이어 씁니다. 기존의 합쳐진 항목은 사용자 데이터를 보호하기 위해 그대로 둡니다.
- `packingDefaults`에 이미 적용한 기본 카테고리·항목 ID를 기록합니다. 사용자가 기본 항목을 수정하거나 삭제해도 적용 이력을 유지하여 다음 실행이나 백업 복원 때 다시 생성하지 않습니다. 삭제한 기본 카테고리는 향후 새 기본 항목이 생겨도 되살리지 않습니다.
- 이전 앱에는 삭제 이력과 고정 ID가 없었습니다. 최초 마이그레이션 시 과거에 삭제하거나 이름을 바꾼 항목과 새 기본 항목의 관계는 식별할 수 없습니다. 기존 내용은 그대로 보존하고 새 목록을 추가합니다. 기존의 삭제된 구형 기본 묶음은 다시 생성하지 않습니다.
- 업데이트를 위해 저장 데이터를 지울 필요가 없습니다. 다른 탭에서도 앱을 열어 두었다면 모두 새로고침해 주세요.

### 기본 목록 유지보수와 검증

`PACKING_DEFAULTS`의 ID는 영구 식별자입니다. 이름 수정·순서 변경 시에도 ID를 유지하고, 삭제한 ID는 다른 항목에 재사용하지 마세요. 새 항목과 카테고리에는 새로운 ID를 지정하면 마이그레이션이 아직 적용하지 않은 ID만 추가합니다. 기존 데이터 구조를 바꾸는 후속 변경에는 별도 마이그레이션이 필요합니다.

`node tests/migration.cjs`로 개수, 기존 데이터 보존, 중복 방지, 수정·삭제·정렬 유지, 미래 기본 항목 추가, 백업 이력 검증을 실행할 수 있습니다.

### 백업 이용

- 백업 저장으로 JSON 파일을 내려받고, 백업 복원으로 다시 불러옵니다. 복원은 기존 데이터를 교체하므로 먼저 백업하세요.
- 기기·브라우저·사이트 주소·포트가 달라지면 저장 공간도 다릅니다. 이동 전 백업 후 새 주소에서 복원하세요. 브라우저 데이터 삭제나 비공개 모드 종료로 데이터가 사라질 수 있습니다.
- **☁ 함께 쓰기**로 Supabase 저장소에 연결하고 같은 계정으로 로그인하면 PC·폰에서 목록을 공유합니다. 최초 연결 방법은 [SYNC_SETUP.md](SYNC_SETUP.md)를 확인하세요. 연결 전에는 기존과 같이 기기에만 저장합니다.

## GitHub Pages 적용

1. 변경을 `main` 브랜치에 푸시합니다: `git push origin HEAD:main`
2. GitHub 저장소의 **Settings → Pages → Build and deployment**에서 **Deploy from a branch**를 선택합니다.
3. 브랜치를 **main**, 폴더를 **/(root)**로 지정하고 저장합니다.
4. 배포가 끝나면 `https://igyeonga88-lgtm.github.io/travel-checklist/`에서 사용할 수 있습니다.

업데이트는 같은 경로의 `index.html`을 수정해 커밋·푸시하면 됩니다. 실제 배포 주소는 GitHub Pages 설정에서 확인하세요.
